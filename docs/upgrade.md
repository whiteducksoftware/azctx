# Upgrading to azctx 2026.11

This guide tracks breaking changes from 2024.12.5. Later release layers add
their changes to the table below.

## Breaking changes

| Area | Change | Who is affected | What to do |
| --- | --- | --- | --- |
| Future release packages | macOS moves from the deprecated formula publisher to a macOS-only cask with declarative quarantine removal for unsigned binaries; Chocolatey/winget require Azure CLI >=2.61.0 and skip prerelease publishing. | Package users and release maintainers. | See [release configuration](releasing.md). This layer publishes nothing and does not migrate the tap or establish tap trust; those remain #100 acceptance. Portable publishers use Ubuntu block mode; full native Windows/macOS enforcement is unmet and the release workflow fails closed until reviewed enforcement and acceptance exist. Releases default to not-latest until package availability is verified. |
| Contributor integration checks | The existing real-binary/fake-az suite runs on all three CI platforms; `make test`/`make check` now report statement-weighted `internal/` coverage and require at least 70%, with no `cmd/` gate. | Contributors and CI maintainers. | See [integration tests](integration-tests.md) for `make e2e`, offline policy tests and the opt-in dedicated-test-tenant OIDC nightly. A skipped nightly is not live acceptance; no tenant was supplied or live run verified during implementation. |
| Hardening and redaction | Verbose, doctor, error diagnostics and Azure CLI stderr redact recognized token-shaped values, including tokens split across writes. Login children receive interrupts before a bounded cancellation fallback. | Troubleshooting and login users. | Expect `[REDACTED]` in diagnostics; stdout data and explicit `exec` child streams are unchanged. Filtering is heuristic, not a substitute for avoiding secrets in logs/argv. IDs derived from local data remain GUID-validated; only the user's explicit login arguments after `--` retain the passthrough exception. See [diagnostic boundaries](cli-contract.md#executable-and-diagnostic-boundaries). |
| Windows builds | The 32-bit `windows/arm` build is removed; Windows on ARM64 remains supported. | Users of the 32-bit Windows ARM binary. | Move to a supported 64-bit Windows system and use the `windows/arm64` or `windows/amd64` binary. |
| macOS | macOS 13 or later is required by Go 1.27. | Users running macOS 12 or earlier. | Upgrade to macOS 13 or later before installing azctx 2026.11. |
| Windows | Windows 10 or later is required by Go 1.27. | Users running older versions of Windows. | Upgrade to Windows 10 or later before installing azctx 2026.11. |
| Source builds | The minimum Go version is 1.26; the preferred toolchain is Go 1.27.3. | Contributors and users building azctx from source. | Use the Go version and toolchain declared in `go.mod`; allow automatic toolchain selection (the default) rather than setting `GOTOOLCHAIN=local` with an older Go installation. |
| Go security patch | Go 1.27.3 fixes [GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809) in `crypto/x509.Certificate.Verify`, used by the update check. | Contributors and users building azctx from source. | The preferred toolchain advances from 1.27.2 in the CI layer rather than waiting for a later dependency layer, because the newly published reachable standard-library issue needs a security patch, not a vulnerability waiver. The Go 1.26 source floor is unchanged; Go 1.26 users must use at least 1.26.10 if opting out of automatic toolchain selection. |
| Diagnostic output | Logrus-style timestamps and `INFO[0000]`/`level=info` output are removed. Messages, warnings, login progress and update notices go to stderr as plain text; `azctx -c` data goes to stdout. | Scripts parsing logs or redirecting current-subscription output. | Consume stdout for data and stderr for diagnostics; do not parse logging prefixes. |
| Picker | The picker now uses a fuzzy-filterable Bubble Tea list with name, subscription ID and tenant columns. Narrow terminals drop subscription ID, then tenant; the terminal bell is never used. | Interactive users. | Press `/` to filter, arrows to navigate and Enter to confirm the filter, then select. |
| Picker interruption | Ctrl+C exits with status 130, including when choosing among multiple name matches. | Interactive users and shell scripts. | Treat 130 as interruption rather than successful selection. |
| Login progress | Animated spinners and forced color formatting are removed. | Interactive login users and scripts. | Read the plain progress messages on stderr; Azure login behavior is otherwise unchanged. |
| Version formats | `azctx version` defaults to text and accepts only `-o text` or `-o json`; `-o short`, `-o yaml` and `-o pretty` are removed. The command no longer fetches an upgrade notice. | Users and scripts invoking `version`. | Use text for humans or JSON for automation. JSON reports `version`, `buildDate`, `commit` and `goVersion`; unavailable build metadata is `unknown`. |
| Subscription matching | Names, tenant names and subscription IDs are searched without collapsing equally named subscriptions. Multiple matches show a picker with tenants; sorting is deterministic. | Users with duplicate subscription names or multiple tenants. | Use a unique name, tenant name or ID with `azctx -- QUERY`, or filter the picker by those fields. All subscription IDs passed to Azure CLI must be valid GUIDs. |
| Previous subscription | `azctx -` now swaps the last two subscriptions across processes using private `os.UserConfigDir()/azctx/state.json`. | Users switching repeatedly between subscriptions. | Switch once before using `-`. Keep azctx's user configuration outside `AZURE_CONFIG_DIR`; state files use `0600` permissions and their directory uses `0700` on Unix. |
| Update checks | Stable CalVer checks use the latest-release redirect at most daily, cache attempts/results in `os.UserCacheDir()/azctx/update.json`, and have a two-second network deadline. Failures never change a successful switch's exit status. | Interactive users, offline users and automation. | Set `AZCTX_NO_UPDATE_CHECK=1` to opt out. Checks are also skipped when stdout is not a TTY or `CI` is set. Keep the private cache outside `AZURE_CONFIG_DIR`. |
| Update cache recovery | Malformed update caches are refreshed without failing a successful switch; their JSON error is reported only with `--verbose`. Missing caches remain quiet. | Users troubleshooting update checks. | Use `--verbose` to see malformed-cache diagnostics; no manual cache removal is needed. |
| Login streams | `az login` is attached to stdin/stdout/stderr, with stderr teed into a diagnostic buffer and no spinner. | Device-code login users over SSH, in devcontainers and in Codespaces. | Device codes are shown immediately on the stream Azure CLI uses; `azctx login -- --use-device-code` no longer hides them. |
| Quiet defaults and errors | Unset `AZURE_CONFIG_DIR` silently defaults to `~/.azure`; missing tenant-cache hints and routine switch messages are removed. Picker errors now surface, missing-profile errors recommend `az login`, and wrapped causes are retained. | Interactive users and scripts inspecting errors. | Use `--verbose` for debug diagnostics, including nonfatal update failures. Ctrl+C remains exit 130. |
| Bare command in automation | Bare `azctx` prints the subscription table instead of opening a picker when input is disabled. | Pipelines, redirected stdin and AI agents. | Use `azctx list` explicitly or consume bare-command stdout; a Ctrl+C byte in a pipe is data, not a terminal interrupt. |
| Positional and qualified queries | `azctx QUERY` now switches without requiring `--`; `tenant/subscription` scopes a query to an exact tenant ID, profile display name or default domain. Names equal to commands still require `azctx -- NAME`. | Interactive users and scripts selecting duplicate names. | Prefer an exact subscription ID or qualified query. Use IDs for subscription names containing literal `/`. Profile tenant names, domains and IDs also participate in unqualified search and picker filtering. |
| Current-subscription formats | `azctx -c` supports `-o text\|json\|id\|name\|tenant`; it no longer accepts a query alongside `-c`. | Scripts parsing the human active-subscription line. | Use `-o id`, `name` or `tenant` for a single field, or versioned JSON for structured data. |
| Subscription listing | `azctx list [-o table\|json]` is available; tenant-level accounts are hidden by default. `list --all` includes them. | Users inspecting profiles and tenant-level accounts. | Use `list --all` rather than changing the old global tenant filter. |
| Removed short-prompt flags | `--short` and `-s` are removed and now fail with exit 1, not a deprecation warning. | Scripts and aliases retaining legacy prompt-size flags. | Remove the flags; picker width is automatic. |
| Removed tenant-filter flag | `--filter-tenant-level` is removed and now fails with exit 1. | Scripts changing tenant-level filtering. | Use `azctx list --all` to inspect tenant-level accounts. Switching/picker defaults remain filtered. |
| Input controls | Persistent `--no-input` and `AZCTX_NO_INPUT=1` disable azctx-owned pickers/prompts. Non-TTY stdin or a present `CI` also disable them. | CI jobs, agents and users scripting azctx. | Use unique queries; ambiguous non-interactive runs exit 2 with candidates instead of waiting. Login remains an attached Azure CLI wrapper, not a new unattended-authentication mode. |
| Exit statuses | The stable table is 0 success, 1 error, 2 no/ambiguous match, 3 sign-in failure, 4 guard mismatch and 130 Ctrl+C. An `exec` child passes through its own arbitrary status. | Scripts previously treating every error as 1. | Branch on the documented command's status. Missing previous state remains 1; Unix child signal exits use `128 + signal`. |
| Versioned subscription JSON | List/current JSON carries `schemaVersion: 1` in list/current envelopes; every subscription/candidate has the same complete fields, including profile-backed tenant metadata and delegation. | Structured-output consumers. | See [the CLI contract](cli-contract.md); tolerate additive fields and inspect `schemaVersion`. |
| JSON errors and streams | `-o json` failures, including invalid flags, emit exactly one JSON object on stderr; stdout is reserved for successful data. JSON switches are quiet, disable pickers/updates and suppress verbose diagnostics. | Scripts, CI jobs and AI agents. | Read `code`, `message`, `exit_code` and ambiguity `candidates` from stderr. Use text mode for debug diagnostics; flags after `--` are literal arguments. |
| Persistent output and color | `-o`/`--output`, `--verbose` and `--no-input` work before/after subcommands. Bare `-o table\|json` requests a list even with a TTY. Non-TTY output and any present `NO_COLOR` disable azctx colors, overriding forced-color requests. | Shell aliases, redirected-output consumers and accessibility users. | Choose a supported per-command format. Set `NO_COLOR` for uncolored interactive output. |
| Minimum Azure CLI | Azure CLI **2.61.0 or newer** is required. Login checks `az version -o json` using its `azure-cli` value; switches do not run the slow version command. | Users wrapping login with azctx. | Upgrade Azure CLI before `azctx login`; missing, malformed or unsupported versions fail before login. |
| Profile-backed tenants | Names/domains come from `tenantDisplayName`/`tenantDefaultDomain` in `azureProfile.json`, including after plain `az login`. azctx no longer reads/writes `azctxTenants.json` or calls the tenants REST API. | All users, especially users of older profiles. | Delete any leftover `azctxTenants.json` yourself if desired. Labels prefer display names, then default domains, then tenant IDs. Run `az login` once when a displayed record lacks both modern fields; only then is a one-line human-output hint shown. JSON and plain-field formats remain quiet. |
| Hidden subscriptions | Disabled, tenant-level and foreign-cloud accounts are hidden by default; entries missing `environmentName` are also hidden rather than guessed to belong to a cloud. | Users listing, selecting or returning to previous subscriptions. | Use `azctx list --all` to inspect every entry. Foreign-cloud records never appear current or become selectable; change the active cloud using Azure CLI first. |
| Subscription details | Tables/picker show user, service-principal and system/user-assigned identity labels, and mark `Warned`/`PastDue`. Different nonempty `homeTenantId`/`tenantId` values identify Lighthouse delegation; `managedByTenants` remains profile data. | Users with workload identities, delegated access or attention states. | Inspect state/account/access labels or the unchanged version-1 JSON fields; JSON `delegated` is now populated and raw user fields are preserved. |
| Azure settings and cloud defaults | azctx reads INI `config` and per-cloud `clouds.config` without writing them. Keys and booleans are case-insensitive, sections are case-sensitive, and `AZURE_{SECTION}_{NAME}` overrides settings. Absent, empty or whitespace-only cloud names default to `AzureCloud`. | Users with sovereign or custom clouds and per-cloud defaults. | An active-cloud profile `isDefault` wins; otherwise its remembered GUID in `clouds.config` is used only if it uniquely matches that cloud. Missing/stale/ambiguous defaults are not guessed; malformed INI is an error. |
| Azure login selector | Wrapped `az login` alone receives `AZURE_CORE_LOGIN_EXPERIENCE_V2=off`. Version checks, switches and the caller's environment are unchanged. | Users of Azure CLI's 2.61+ subscription picker. | Continue choosing subscriptions with azctx; no persistent Azure setting is changed. Existing attached device-code streams are preserved. |
| First login | `azctx login` can start without an Azure directory or profile, still checking the minimum Azure CLI version before sign-in. | Fresh installations and new `AZURE_CONFIG_DIR` locations. | Let the wrapped Azure CLI create its own files. azctx never creates them; listing and switching still require an existing readable profile. Malformed existing settings remain explicit errors. |
| Broker-aware login | Progress follows effective Windows WAM/macOS broker/browser settings. macOS broker is a 2.91.0+ opt-in preview requiring an enrolled device and Enterprise SSO plug-in. | Interactive sign-in users. | Follow the matching account picker/browser instructions; settings and `AZURE_CORE_*` overrides are respected. |
| Friendly login flags and headless hints | `azctx login --use-device-code` and `--tenant <name\|id>` no longer need `--`. SSH/Codespaces/devcontainer sessions and Linux without displays get a device-code suggestion before sign-in. | First-login and remote users. | Use a tenant GUID without a profile; fuzzy profile names/domains must identify one active-cloud tenant. Do not combine friendly `--tenant` with `--all-tenants` or another passthrough tenant flag. Other flags still go after `--`. |
| MFA-aware multi-tenant login | `--force-mfa` is removed. Ordinary login lists documented failed tenants and offers one default-yes confirmation to retry only MFA-required/registration tenants (50076/50079); Conditional Access blocks (53003) are explained, other errors remain verbatim. | Multi-tenant users, scripts and workload identities. | Use plain `azctx login` for targeted recovery or `--all-tenants` for explicit discovery through `az account tenant list`. Known non-retryable failures are never repeated. No-input/CI/piped runs list initial failures without retry/discovery and exit **3**; unresolved/declined/partial sign-ins also exit 3. Completed attempts summarize reloaded profile totals. `--identity`/`-i` and `--service-principal` passthrough skip retry/discovery, even with `--all-tenants`. See [authentication](authentication.md); live-tenant acceptance is unverified. |
| Confirmed broker controls | New `auth broker status\|enable\|disable`; enable/disable explicitly confirm `az account clear`, persisted platform `az config set`, then attached `az login`. This is the sole Azure-configuration-write exception; azctx still never directly writes Azure files or accesses credentials/token caches. | Windows >=2.61.0 and macOS >=2.91.0 users changing broker mode. | Confirm on a TTY or use `--yes` explicitly. No-input/CI/piped runs without confirmation, conflicting environment overrides and unsupported platforms/versions cannot mutate. Failures stop at the first step; retry login if settings persisted. |
| Offline doctor | New profile-independent `azctx doctor [-o text\|json]` reports version/path, cached update status, profile/settings/cloud/account types and manual leftover tenant-file cleanup. No live update/Azure request, credentials or identities are printed. | Troubleshooting users and support automation. | Consume the separate doctor schema-1 JSON report on stdout; warnings are findings, not failed commands. The legacy file is only statted, never read/deleted. See [authentication](authentication.md). |
| New command names and cancellation | `auth` and `doctor` are command names; explicitly canceled command contexts preserve interruption status 130. | Users with equally named subscriptions and embedded command callers. | Use `azctx -- auth` or `azctx -- doctor` for literal subscription queries. Existing stdout/error envelopes and subscription DTOs remain unchanged. |
| Strict configuration and aliases | New `config [path]` and `alias set\|rm\|list` commands use strict version-1 `config.yaml`; missing files use defaults, invalid files report their line and reject unknown keys. | Users adding aliases or preferences. | See [configuration](configuration.md) for the exact schema. `AZCTX_CONFIG_DIR` overrides the azctx directory for configuration **and state**, never Azure files; alias updates rewrite canonical YAML while preserving other settings. Use `azctx -- alias` or `azctx -- config` for those literal subscription names. |
| Exact matching and ranking | Exact IDs win, then exact names/aliases, then fuzzy fields. Name/alias collisions preserve all identities; pinned subscriptions/tenants precede most-recently-used IDs in the picker. Private state adds `recentSubscriptionIds` and rolls it back with previous state on a failed switch. | Users with similar names, aliases or many subscriptions. | Use IDs or qualified queries to disambiguate. Priority never automatically resolves an ambiguity; no-input ambiguities still exit 2. |
| Configured hidden entries | `hidden` excludes configured subscription/tenant IDs from selection, listing and completion. Root `--all` exposes them; `list --all` still additionally shows Azure-filtered records. | Users managing large profiles. | Use `azctx --all QUERY` for an explicitly hidden subscription. Existing active-cloud, enabled-account switching restrictions remain; current output still identifies the actual current subscription. |
| Protected switching | `protected` subscription/tenant IDs require terminal confirmation or root `--yes`, including alias, picker and previous routes. Current text adds `[protected]`; subscription JSON and plain-field current formats are unchanged. | Production operators and scripts. | Use `--yes` only to explicitly approve the protected switch. No-input/JSON runs without it exit 1 without mutation; declining confirmation leaves state unchanged. |
| Update opt-out and completion | `updateCheck: false` suppresses all post-switch update work. Completion supplies names, aliases and qualified names directly from profile/config without Azure execution, network requests or state writes. | Offline users and shell users. | Existing update environment/TTY/CI/JSON gates remain. Generate bash, zsh, fish or PowerShell scripts with `azctx completion SHELL`. |
| Tenant-first selection and fzf | New `tenant [query]` selects a tenant by GUID/name/domain, then a subscription. Duplicate names never merge tenant identities; a unique tenant with one subscription switches directly. `picker: fzf` now invokes optional fzf on `PATH`, with one-line built-in fallback if missing. | Multi-tenant and Lighthouse operators. | Use `azctx tenant`, or exact tenant GUIDs. No-input/JSON ambiguity still exits 2; protection and cloud/state restrictions remain. `--all` permits disabled-account inspection, not unsafe switching. fzf defaults/bindings are intentionally ignored; Ctrl+C remains 130. Lighthouse and Warned/PastDue markers remain visible in list/picker labels. |
| Completed-switch history | New `history [-o text\|json]` shows at most 100 completed switches with UTC timestamp, previous/new GUID+cloud identities and terminal/script source. Private atomic `history.json` lives next to state and honors `AZCTX_CONFIG_DIR`. | Operators inspecting azctx-made switches. | See [the format and limitations](configuration.md#completed-switch-history). Failed switches never append. Corrupt history is ignored with a warning; write/busy-lock failures warn without failing an already-completed switch, even in JSON mode. No raw user/secret fields are stored. Use `azctx -- tenant` or `azctx -- history` for subscriptions matching the new command names. |

## Environment, execution and guards

| Area | Change | Who is affected | What to do |
| --- | --- | --- | --- |
| Environment export | `env [query]` exports `ARM_SUBSCRIPTION_ID`, `ARM_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`, `AZURE_TENANT_ID` in bash (default), zsh, fish or PowerShell syntax. | Terraform/azd/SDK users and scripts. | Validate command success before evaluating exports. Queries reuse alias/hidden/ambiguity policy without switching or prompting, including protected targets. Both IDs must be GUIDs. Azure CLI ignores these variables: pass `--subscription`. |
| Pipeline exports | `env --format github` retains/appends to existing `GITHUB_ENV` with no stdout; `--format azure-devops` emits setvariable logging commands. | CI authors. | Shell/format flags are exclusive. GitHub requires an existing absolute writable regular file outside Azure config, without symlinks/hard links, at most 8 MiB; it is atomically replaced without changing parent permissions. Pipeline variables apply to subsequent steps/tasks, not the current shell. See [CI/CD](ci-cd.md). |
| Isolated execution | `exec QUERY -- COMMAND [ARGS]` resolves the executable once without a shell and sets only child context variables. It attaches streams, forwards signals/Ctrl+C and preserves child exit status; explicit cancellation exits 130 with a bounded kill fallback. | Script authors and per-terminal users. | The delimiter is mandatory; child arguments are literal. The parent environment, Azure default and azctx state/history are unchanged. `-o json` formats preflight errors, never the child's output or exit diagnostics. Requested children still own their side effects. |
| Project guards | `guard` checks the nearest `.azctx.yaml`, requiring a single strict version-1 document with tenant/subscription GUIDs. Explicit `--subscription`/`--tenant` flags replace project expectations. | Repository and deployment authors. | Match is silent 0; mismatch 4; missing/malformed file 1. A malformed nearer file never falls back to an ancestor. Treat cloned files as untrusted: azctx never automatically switches, logs in or records state/history because of them. |
| Current warnings and new names | Human `-c` warns on project mismatch/invalid project without failing; JSON/plain fields remain unchanged. `env`, `exec` and `guard` are now command names. | Interactive operators, prompt consumers and subscriptions with those names. | Use `azctx -- env`, `azctx -- exec` or `azctx -- guard` for literal subscription queries. Use JSON/plain current fields for machine consumers. These read-only commands never run updates or invoke Azure CLI. |

## AI agents

| Area | Change | Who is affected | What to do |
| --- | --- | --- | --- |
| Agent Skill and Claude plugin | Versioned `skills/azctx/` guidance and an optional Claude Bash `PreToolUse` guard are available through this repository's plugin marketplace. | Claude Code, Copilot, Codex and Cursor users. | See the draft [AI agent guide](ai-agents.md). Inspect JSON context, use explicit Azure CLI subscription IDs and isolated exec for environment-aware tools; leave authentication/protected switching to the user. The hook needs Python 3.10+ and azctx on PATH; absent azctx/project emits a notice and allows, any guard failure blocks. These mistake-reduction tools are no security boundary: Azure RBAC, PIM and Conditional Access still control access. |

## Upgrade checklist

- Check the breaking changes above before upgrading.
- Choose a binary for your operating system and architecture: Linux
  (`amd64`, `arm64`, `arm`), macOS (`amd64`, `arm64`), or Windows (`amd64`, `arm64`).
- Follow the [installation instructions](../README.md#installation) for your
  package manager or binary installation.

## Contributor and maintenance changes

| Area | Change | Who is affected | What to do |
| --- | --- | --- | --- |
| CI checks | Every pull request (including stacked branches) and push to `main` runs race-enabled tests on Linux, macOS and Windows, Go/workflow linting, module verification and vulnerability scanning; Linux and Windows snapshot builds never publish. | Contributors. | Run `make check` before opening a PR and resolve failing checks. All reachable vulnerability findings and scanner errors fail; the layer 02 temporary x/text exceptions have been removed after the dependency upgrade. |
| Hardening checks and reproducibility | Six strict linters and assertion checks are explicitly enabled; CI fuzzes each of the profile/config/project parsers for 60 seconds. Builds disable CGO, use `-trimpath` and GoReleaser derives binary timestamps and `BuildDate` from the commit. | Contributors and binary builders. | Run `make check` and `make fuzz`; the latter uses only offline synthetic corpora. Release workflow permissions/environments remain layer-17 work. Branch configuration is not evidence of a clean remote-main OpenSSF Scorecard run. |
| Dependency and build metadata | Legacy UI, logging, filesystem and version dependencies are replaced with Bubble Tea/Bubbles/Lip Gloss, sahilm/fuzzy, x/term and the standard library. Both release configs now set `internal/version.Version`, `BuildDate` and `Commit` under the module import path. | Contributors and custom binary builders. | Use the new ldflags when building release binaries; Go build information supplies fallback metadata. Run `make golden` for intentional picker screen updates. The Go 1.26 language floor and preferred Go 1.27.3 toolchain are unchanged. |
| Dependency updates | Go module and GitHub Actions minor/patch updates are grouped per ecosystem, with a three-day cooldown and at most one open version-update PR per ecosystem. | Maintainers. | Review the weekly grouped updates; major updates remain separate and share the same version-update PR limit. Security updates are not delayed by the cooldown or this limit. |
| Security posture | OpenSSF Scorecard runs on pushes to `main` and weekly, uploading SARIF to GitHub code scanning without publishing externally. Existing CodeQL remains enabled. | Maintainers. | Review the security results. Release-workflow credential-persistence, broad-permission and setup-go cache findings are precisely location-excepted until layer 17 (#98); snapshot jobs disable setup-go caching and all other workflow audits remain active. |
